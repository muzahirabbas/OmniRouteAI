# Frontend Playground Errors - Complete Fix Plan

## Summary
Two main errors are causing the frontend playground to fail:
1. `response.json is not a function` - Browser cache serving old `api.js` where `streamRequest` returns `response.body`
2. `include_reasoning is not defined` - Helper functions `toOpenAIResponse` and `toResponsesAPIFormat` don't have `include_reasoning` in scope

---

## Issue 1: `response.json is not a function` (Streaming)

### Root Cause
**File:** `frontend/js/api.js` (line 327)

**Status:** PARTIALLY FIXED - The code was changed to `return response;` but the browser is likely serving cached old code.

The `streamRequest` function now correctly returns the full `Response` object (fixed in previous commit). However, the browser may have cached the old `api.js` where `streamRequest` returned `response.body` (ReadableStream).

### Fix Already Applied
**File:** `frontend/js/api.js` line 327
```javascript
// Fixed: return response; (instead of return response.body;)
```

### Additional Steps Required
1. **Clear browser cache**: User must do a hard refresh (Ctrl+F5 or Cmd+Shift+R)
2. **Add cache-busting to `index.html`**: Add version parameters to script tags

---

## Issue 2: `include_reasoning is not defined` (Non-Streaming)

### Root Cause
**File:** `src/routes/chat.js`

The helper functions `toOpenAIResponse` (line 286) and `toResponsesAPIFormat` (line 328) use `include_reasoning` but it's NOT in their parameter list.

These functions are defined OUTSIDE `handleChatRequest` (line 389), so they cannot access the `include_reasoning` variable that's destructured inside `handleChatRequest` at line 396.

**Bug locations:**
- Line 301: `toOpenAIResponse` uses `include_reasoning` but doesn't receive it as parameter
- Line 366: `toResponsesAPIFormat` uses `include_reasoning` but doesn't receive it as parameter

**Call sites that need updating:**
- Line 489: `toResponsesAPIFormat({ ...cached, model: cached.model }, requestId)` → needs `include_reasoning`
- Line 496: `toOpenAIResponse({ ...cached, model: cached.model }, requestId, false)` → needs `include_reasoning`
- Line 683: `toResponsesAPIFormat(result, requestId)` → needs `include_reasoning`
- Line 691: `toOpenAIResponse(result, requestId, false)` → needs `include_reasoning`
- Line 742: `toResponsesAPIFormat(result, requestId)` → needs `include_reasoning`
- Line 750: `toOpenAIResponse(result, requestId, false)` → needs `include_reasoning`

### Fix
1. **Update `toOpenAIResponse` function signature** (line 286):
```javascript
// OLD:
const toOpenAIResponse = (result, requestId, stream = false) => {

// NEW:
const toOpenAIResponse = (result, requestId, include_reasoning, stream = false) => {
```

2. **Update `toResponsesAPIFormat` function signature** (line 328):
```javascript
// OLD:
const toResponsesAPIFormat = (result, requestId) => {

// NEW:
const toResponsesAPIFormat = (result, requestId, include_reasoning) => {
```

3. **Update all call sites** to pass `include_reasoning`:
- Line 489: `toResponsesAPIFormat({ ...cached, model: cached.model }, requestId, include_reasoning);`
- Line 496: `toOpenAIResponse({ ...cached, model: cached.model }, requestId, include_reasoning, false);`
- Line 683: `toResponsesAPIFormat(result, requestId, include_reasoning);`
- Line 691: `toOpenAIResponse(result, requestId, include_reasoning, false);`
- Line 742: `toResponsesAPIFormat(result, requestId, include_reasoning);`
- Line 750: `toOpenAIResponse(result, requestId, include_reasoning, false);`
